# STAR 칸 나누기 시험 자료(`/star`, S-95)

SAMPLE(star-samples): 활동 · 경험 · 근거 · 보완 전부 **지어낸** 것이다. 실제 사람 · 기록이 아니다(공개 레포).
PM 의 실제 노트(`developer MOC.txt`) · 경험MAP 작성본은 모양만 참고했고 글은 옮기지 않았다.

- 채점: `uv run python scripts/eval_star.py` — 숫자의 뜻은 스크립트 머리말
- `activities.json` — 활동 4개(요청 하나씩) · 경험 20개
  - `moc` 이름만 있는 활동 — 노트 제목 같은 짧은 근거 · 근거 없는 경험 · 「결과물 만족하지 않음 … 참고만」(다른 서비스가 교훈을 지어 넣은 그 경우 — ETC#324)
  - `retro` 회고 — 근거에 배운 점 · 느낀 점 · 다짐 문장이 섞여 있다(R 에 쓰면 안 된다) · 보완 답의 배운 점(R 에 쓴다)
  - `readme` 팀 README — 수행 주체 `TEAM` · `UNKNOWN` 이 많다(T 를 근거로 못 채운다) · 결과 수치
  - `club` 동아리 홍보 — 비개발 · 한 근거에 S · T · A · R 이 다 든 경우 · 갈등

| 칸 | 뜻 |
| --- | --- |
| `expect.S` … `expect.R` | 사람 판정. `[]` 빈칸이어야 함 · `["C2011", "P3051"]` 이 출처(C 근거 · P 보완) 중 하나로 채워야 함 · `null` 어느 쪽도 틀렸다고 하기 어려움(안 셈) |
| `learned` | 근거 속 배운 점 · 느낀 점 · 다짐 문장(근거 글 그대로) — R 칸 글이 이 문장과 겹치면 「만들어 낸 배운 점」. 같은 근거의 결과 사실(「같은 실수가 줄었다」)을 R 에 쓰는 건 된다 |

정답은 AI 에이전트가 초안을 썼다 — 팀원이 보고 고친다. ID 가 실제 근거 · 보완을 가리키는지는 `tests/test_eval_star.py` 가 본다.
